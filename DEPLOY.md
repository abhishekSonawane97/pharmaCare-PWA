# Deployment guide — Render.com (free tier)

This walks through deploying PharmaCare to Render, free tier, no credit card required. Total time: ~30 minutes.

## Architecture

```
   Public Internet
        │
        ▼
┌────────────────────────────┐    ┌──────────────────────┐
│  pharmacare-web.onrender   │    │  MongoDB Atlas       │
│  Next.js, port 10000       │    │  (M0 free, Mumbai)   │
│  /api/* → proxy ─────┐     │    └──────────────────────┘
└──────────────────────│─────┘                ▲
                       ▼                      │
┌────────────────────────────┐                │
│  pharmacare-api.onrender   │────────────────┘
│  Express, port 10000       │  reads MONGO_URI
└────────────────────────────┘
```

Two free Render web services + one free Atlas cluster. Cost: ₹0/month.

## Prerequisites

- ✅ MongoDB Atlas connection string (already done)
- ✅ Code pushed to GitHub (see [GITHUB.md](GITHUB.md) below if not done yet)
- ✅ Render account at <https://render.com> (free signup, email-only)

## Step 1: Connect GitHub to Render

1. Sign in to <https://render.com>
2. **New** (top-right) → **Blueprint**
3. **Connect a repository** → install the **Render** GitHub app on your account → pick the `pharmacare` repo (or whatever you named it)
4. Render auto-detects [`render.yaml`](render.yaml) at the repo root and shows you both services it'll create:
   - `pharmacare-api` (Docker, free)
   - `pharmacare-web` (Docker, free)
5. Click **Apply**

## Step 2: Set the secret env vars (the ones marked `sync: false`)

Render asks you to fill in these values during the Blueprint setup. Paste from your local `.env`:

**For `pharmacare-api`:**
| Variable | Value |
|---|---|
| `MONGO_URI` | `mongodb+srv://pharmacare:<password>@<cluster>.mongodb.net/pharmacare?retryWrites=true&w=majority` |
| `ADMIN_PASSWORD` | The password you want for the first admin login |

JWT secrets are auto-generated by Render (`generateValue: true` in `render.yaml`). The CORS origin and proxy target wire themselves between services automatically.

Click **Apply** → Render starts building.

## Step 3: Wait for first build (~5–10 min)

Both services build their Docker images and deploy. Watch the logs in Render's dashboard:
- **api** is ready when logs show `[mongo] connected` and `[api] listening on :4000`
- **web** is ready when logs show `Ready in Xs` (Next.js)

Once both go green:
- API URL: `https://pharmacare-api.onrender.com`
- Web URL: `https://pharmacare-web.onrender.com` ← share this with your client

## Step 4: Seed the database (first time only)

The seed script wipes Atlas and inserts sample data. Run it **once** from your local machine (not on Render — it's one-shot):

```bash
# From your local project root
docker compose exec -e SEED_FORCE=true api npm run seed
```

Or, if you've torn down the local stack, run the seed against Atlas directly:
```bash
cd apps/api
MONGO_URI="<your atlas uri>" \
ADMIN_EMAIL="admin@pharmacare.local" \
ADMIN_PASSWORD="<your admin password>" \
SEED_FORCE=true \
npx tsx src/scripts/seed.ts
```

If you migrated production data via `mongorestore` already, **skip seeding** — your real data is in Atlas.

## Step 5: Test it

1. Open `https://pharmacare-web.onrender.com`
2. **First visit may take 30–60 seconds** — Render free tier spins down after 15 min of idle. That's normal.
3. Log in with `admin@pharmacare.local` and the `ADMIN_PASSWORD` you set in step 2

## Step 6 (recommended): Keep it warm

Render free services sleep after 15 min of inactivity. To avoid cold starts during your client demo, set up a free uptime pinger:

1. <https://uptimerobot.com> (free, no CC)
2. Add monitor: HTTP keyword, URL = `https://pharmacare-api.onrender.com/api/health`, interval = 5 minutes
3. UptimeRobot's pings keep the api warm; the web service shares the load

## Auto-deploy on every push

Once connected, **every `git push` to `main` automatically triggers a redeploy** on both services. No manual steps after the first time.

## Updating env vars later

1. Render dashboard → `pharmacare-api` → **Environment** tab
2. Edit values, then **Save Changes** → Render redeploys api in ~1 minute

## Custom domain (optional)

1. Buy a domain (e.g. `pharmacare.in` from a registrar)
2. Render dashboard → `pharmacare-web` → **Settings** → **Custom Domain** → add yours
3. Add the DNS record Render shows (CNAME or A)
4. Render auto-provisions HTTPS via Let's Encrypt — done in ~2 minutes

## Tearing it down

- Render dashboard → click each service → **Settings** → **Delete Service**
- Atlas data is independent — delete the cluster from Atlas separately if you want to remove everything

## Troubleshooting

| Symptom | Fix |
|---|---|
| Build fails: "no Dockerfile found" | Verify `dockerfilePath` and `dockerContext` in `render.yaml` match your repo layout |
| API logs show "MongooseServerSelectionError" | Atlas IP allowlist must include `0.0.0.0/0` (Render IPs aren't static) |
| Web shows "Sign-in failed" | Check that `pharmacare-api` is up; check browser DevTools network tab for the failing `/api/auth/login` call |
| 502 / 503 from web | API is sleeping or building — wait 30–60s and retry |
| Slow cold starts annoy your client | Set up UptimeRobot per Step 6, or upgrade api to **Starter $7/mo** (no sleep) |
